## 一、重要说明与方案选型

本手册总结了针对 项目B 模拟器 6.8.1 版本的全套逆向切入点与微创修复点位。针对不同使用场景，支持两种主流落地形态：

1. **静态十六进制修补 (Binary Hex Patching)**：
   - 使用 HxD / 010 Editor 等工具直接修改 EXE 磁盘文件。
   - 特点：脱离外部依赖，零额外 DLL 加载开销；但会改变文件哈希并破坏官方 Authenticode 数字签名。
2. **DLL 代理运行时内存热补丁 (Proxy DLL Memory Hotpatching)**：
   - 基于系统劫持与导出转发技术（`nx_main\sentry.dll` 覆盖 Main/Service，`nx_main\version.dll` 覆盖 RemoteService）。
   - 特点：**EXE 磁盘文件 100% 保持官方原版，数字签名完全有效 (Valid)**；在进程初始化时由看门狗线程向内存写入同等补丁。

无论采用哪种方案，本手册记录的 **原始字节 (Original Bytes)**、**修补字节 (Patch Bytes)** 与 **语义切入点** 均具备 100% 严格对应关系。

## 三、手动十六进制修复流程

1. **完全退出所有 项目B 进程与后台服务**：
   ```bat
   taskkill /f /im 项目BNxMain.exe /im 项目BNxService.exe /im 项目BNxLauncher.exe /im 项目BManager.exe
   sc queryex 项目BRemoteService
   sc stop 项目BRemoteService
   taskkill /f /im 项目BRemoteBackend.exe /im 项目BRemoteHealthd.exe
   ```
2. **安全备份**：
   ```bat
   copy 项目BNxMain.exe 项目BNxMain.exe.bak
   copy 项目BNxService.exe 项目BNxService.exe.bak
   copy 项目BRemoteService.exe 项目BRemoteService.exe.bak
   ```
3. **定位与修改**：
   - 打开十六进制编辑器，跳转到本文的 **文件偏移 (File Offset)**；
   - **核心纪律**：先核对当前地址的字节是否与下表的「原始字节」完全一致。若一致则覆盖写入「修补字节」；若当前字节短于修补区域，剩余字节必须以 `90` (NOP) 补齐；若不匹配，严禁盲写，说明版本不匹配！
4. **保存并测试启动**。

## 四、核心逆向切入点深度剖析

对比旧版 12.0 (`2ead96f7...`) 与 6.8.1 (`f1f507b9...`)，<厂商>底层代码发生了模块级重排与安全机制重构，以下为 7 大关键切入点及其底层逻辑演化：

### 1. 广告决策分支切入点升级 (Ad-Gate Bypass)
- **12.0 早期方案缺陷**：旧版在 `sub_14012A640` 函数入口直接写入 `mov eax, 1; ret`，虽实现了粗暴返回，但导致 Qt 信号系统无法发送 `member_remove_ad_ok`，启动图与侧边广告抑制链路存在偶发未触发缺陷。
- **6.8.1 精度升级**：通过定位 `.rdata` 唯一字符串 `"member_remove_ad_ok"`（文件偏移 `0x162a9e0`），精准逆向出其信号发射函数 `sub_14012B960`（RVA `0x12b960`）。函数在 `0x14012b99f` 处检测 `cmp byte ptr [rdx + 4], 0`（非会员判定），随后执行条件跳转 `0x14012b9a3: je 0x14012bb62`（跳过信号发射）。
- **切入方案**：将 `0x12ada3` 处的 6 字节 `je` (`0f 84 b9 01 00 00`) 精准替换为 6 个 `NOP` (`90 90 90 90 90 90`)，强制流程直接 fall-through 执行 `member_remove_ad_ok` 信号发射管线，从根源上 100% 抑制开屏推荐广告与侧边横幅。

### 2. 试用与营销 Banner 控制流阻断 (Trial & Promo Flow Bypass)
- **业务逻辑**：程序检测到当前账号未充值或处于免费试用期时，会进入营销导流分支，动态创建推广弹窗与购买引导条。
- **切入方案**：位于 `0xcef5df` (RVA `0xcf01df`)。前置指令为 `cmp qword ptr [r14], 0`，紧随其后的条件跳转 `0f 8e ed 00 00 00` (`jle +0xed`) 用于判断是否进入营销流。直接将其改写为无条件跳转 `e9 ee 00 00 00 90` (`jmp +0xee; nop`)，彻底绕开弹窗逻辑。

### 3. 网络登录回包反序列化特权覆盖 (Network Response Deserialization)
- **业务逻辑**：用户执行登录、Token 刷新或拉取云端配置时，服务端会下发 JSON 载荷，客户端在 `0xd1907a`–`0xd196c6` 区间解析到寄存器/栈帧中。
- **切入方案**：该区间由 6 个连续的 `E8 rel32` (call) 构成。直接将 call 指令替换为 `mov eax, imm32`：
  - 到期时间固定为 `0xF485E67F`（即 2099-12-31，Unix 戳 4102416511）；
  - 会员状态强制置 `1`（VIP）；
  - 会员类型强制置 `1`（VIP 特权）；
  - 设备上限强制置 `5`；
  - 试用状态强制置 `2`（已使用/非活动，不再提示试用体验）；
  - 特权使能标志强制置 `1`。

### 4. 账号缓存解析与持久化双通道 (Account Cache Parse & Serialize A/B)
- **底层架构**：项目B 设计了双解析通道 (`parse_a` / `parse_b`) 与双序列化写出通道 (`serialize_a` / `serialize_b`)，用于在内存与 `configs\main\nx_main.json` 本地配置间双向同步。
- **结构体字段偏移**：6.8.1 版本中，结构体内存布局保持高度稳定：
  - 序列化通道 A 结构体偏移：`+0x2c8`(expiry), `+0x2d4`(status), `+0x2d8`(type), `+0x308`(device), `+0x300`(trial)。
  - 序列化通道 B 结构体偏移：`+0x378`(expiry), `+0x384`(status), `+0x388`(device), `+0x3b0`(type), `+0x3b4`(trial)。
- **切入方案**：对读取字段的汇编指令（如 `mov rax, [rbp+0x2c8]`）直接就地截胡，重写为立即数赋值（`mov eax/ecx, imm32` + `NOP` 填充完整原长），杜绝本地缓存产生脏数据。

### 5. 前台 UI 判定虚表委托直返 (UI Member Check Direct)
- **业务逻辑**：UI 徽标（金色 VIP 图标、专属会员皮肤）是由 UI 渲染线程定时查询管理器对象获取。
- **切入方案**：位于 `0xb50180` (RVA `0xb50d80`) 与 `0xb51c10` (RVA `0xb52810`)，该函数原本负责通过 `[rcx+0x148]` 寻址子对象并跳转其虚表执行布尔判定。直接在函数入口写入 `b0 01 c3` (`mov al, 1; ret`)，实现零栈干扰的即时纯寄存器直返，彻底消除切换界面或刷新时的 VIP 徽标回退闪烁。

### 6. Service 守护服务防回写收敛机制 (NxService Synchronization)
- **逆向死穴（为什么必须改 Service）**：`项目BNxService.exe` 是常驻后台守护，具有最高权限定期将云端或本地账号数据回写到磁盘 `configs\main\nx_main.json`。**若只修改 Main，每次刷新或启动时，Service 就会将旧的非会员状态覆写回磁盘，导致 Main 下次读取又闪回未激活**！
- **切入方案**：同步修补 Service 的 `parse_a` (5点)、`parse_b` (5点)、`serialize` (5点)，同时将账号有效性标志 `is_valid_infos` 两处写死为 `1` (`b0 01 90 90 90` 与 `b1 01 90 90 90 90 90`)，并将云端请求端点 `v1/member/trial` 原地等长替换为 `v1/member/local`，实现本地闭环。

### 7. 远程云控与健康/后端进程阻断 (Remote Control & Healthd Blocking)
- **架构异动**：6.8.1 中 `项目BRemoteService.exe` 体积由旧版的 2.1MB 暴增至 7.79MB（增加了大量跨网映射、云手机及推流支持）。
- **切入方案**：
  - 阻断两处进程启动入口：在 `项目BRemoteBackend.exe` 启动函数（`0xd2740`）与 `项目BRemoteHealthd.exe` 启动函数（`0xd1ae0`）入口处直接写入 `c3 90 90 90 90` (`ret`)，阻断后台私开推流守护；
  - 阻断远程会话判定：定位 RTTI 符号 `platform::isCurrentSessionRemoteSession()`（`0x17d9b0`），在入口写入 `33 c0 c3 90` (`xor eax, eax; ret; nop`)，阻断 `GetSystemMetrics(SM_REMOTESESSION)` 带来的远程状态误判。

## 九、验证要点与排错指南

### 1. 成功现象标准
- **无感秒进**：冷启动或重启时，完全不展示开屏宣传广告与侧边栏推荐应用。
- **特权固化**：主界面头像、多开器列表均展示永久 VIP 徽标，会员有效期固定显示为 **2099-12-31**。
- **免试用打扰**：界面不再出现"剩余试用X天"标签，不弹出购买/充值提醒弹窗。
- **多开与高刷**：支持 5 台以上设备多开与高帧率极致画质模式。
- **后台干净**：任务管理器中不再常驻 `项目BRemoteBackend.exe` 与 `项目BRemoteHealthd.exe` 进程。

### 2. 常见失败原因与排查
- **VIP 状态闪退/一闪而过**：仅修补了 `项目BNxMain.exe`，未同步修补 `项目BNxService.exe`。Service 进程会在后台将真实的非会员信息写入 `configs\main\nx_main.json`，覆盖 Main 的内存状态。
- **修改后程序无法启动 (0xc000007b / 校验报错)**：十六进制修改时填错偏移或漏写了 `90` (NOP)，破坏了后续指令的相对位移；或混淆了 File Offset 与 RVA。
- **文件保存被拒绝**：`项目BRemoteService.exe` 作为 Windows 服务正在运行并持有了句柄，必须以管理员身份先执行 `sc stop 项目BRemoteService` 后方可覆写。
