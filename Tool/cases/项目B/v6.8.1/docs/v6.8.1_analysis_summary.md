## 四、回滚步骤与已知风险

### 4.1 回滚步骤

```powershell
# 1) 完全退出 项目B（含后台服务）
Get-Process 项目BNxMain,项目BNxService,项目BNxLauncher,项目BRemoteService,
            项目BRemoteBackend,项目BRemoteHealthd |
  Stop-Process -Force -ErrorAction SilentlyContinue

# 2) 一键还原（代理按 manifest 哈希识别后删除；sentry.dll 由 sentry_orig.dll 恢复）
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\Restore-ProxyDll.ps1

# 3) 若还需恢复配置
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\Restore-ProxyDll.ps1 -RestoreConfig
```

### 4.2 已知风险

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | **目标版本升级**：三个 EXE 任一哈希变化 | 该组件全部点位失效 | 代理**先逐字节核对再写**，不匹配即 `MISMATCH` 跳过，**不会写坏程序**；部署脚本预检也会拒绝执行；按 §3.5 的底座重新标定 |
| R2 | **官方完整性自校验**：若 项目B 未来增加对 `sentry.dll` 的签名/哈希校验 | 代理会被识别，程序可能拒绝启动或报错 | 当前版本未发现该校验；如出现，改用 `-RestoreProxyDll` 回滚，或改走"挂起启动 + 外部内存补丁"路线（保留全部文件原样） |
| R3 | **服务端权威未攻破**：服务端仍会下发非会员状态 | 若服务端对会员字段做**二次验签/签名绑定**，本地覆盖将失效 | 本方案作用域为**客户端解析/序列化/UI 判定层**；服务端权威需服务端侧整改（见防御建议） |
| R4 | **可选点语义置信度较低** | `nxmain_ui_member_check_direct_b`（同族第二端点）与 `nxremote_is_current_session_remote_session_false`（语义直连，置信度高）中，前者靠平移量单调性裁决 | 设 `GUARD_DISABLE_OPTIONAL=1` 可单独关闭这两点，不影响其余 50 点 |
| R5 | **RemoteService ①a 置信度中等** | `41 0f 95 c7` 虽全二进制唯一，但该模块体积增长 3.66 倍，位置推断依赖"唯一性命中 + 字节完全一致" | ①b（语义直连）已提供独立且更强的远程通道闸门，二者互为冗余 |
| R6 | **到期时间取值** | 统一采用 `0xF485E67F`（≈2099-12-31 16:08 UTC），沿用旧项目已验证取值 | 若 UI 期望毫秒级时间戳，可能显示异常；届时改点位的 `patch_bytes` 即可（单点 5 字节） |
| R7 | **代理 DLL 被误加载到其它进程** | 理论上可能影响无关进程 | 代理内置**模块节区范围校验 + 宿主名分发表**，宿主不匹配即 `SKIPPED`/`OUTOFRANGE`，**零写入**（已实测） |
| R8 | **项目B 常驻服务未重启** | 只部署不重启时，已在跑的 Service 进程仍是旧镜像 | 部署脚本强制要求完全退出；验证清单场景 5 明确要求重启核对 |
| R9 | **杀软误报** | 代理 DLL 为未签名二进制，可能被拦截 | 本机实时防护当前为关闭状态；如需长期使用建议加入排除项 |

## 六、纵深防御整改建议（对厂商侧）

| 层 | 建议 |
|---|---|
| **客户端加固** | ① 将特权判定与广告决策下沉到 Native 并做控制流平坦化；② 对关键决策函数加 `PAGE_EXECUTE_READ` 自校验（周期性 CRC）；③ 增加反调试/反注入（`IsDebuggerPresent` + 模块枚举白名单 + 节区完整性校验）；④ 对 `sentry.dll` 等第三方 DLL 做签名/哈希校验后再加载 |
| **传输层收敛** | ① 会员态接口强制 TLS 双向证书绑定（SSL Pinning）；② 请求体加 `Sign + Nonce + Timestamp`，服务端做重放防护；③ 关键字段（会员状态/到期时间）单独签名，防止客户端篡改后回放 |
| **服务端权威闭环** | ① 核心权益必须以**官方异步通知 + 二次验签**为唯一凭据，禁止盲信客户端上报的本地缓存；② 权益发放与设备绑定使用服务端签发的短期凭证；③ 对客户端序列化结果做服务端校验（服务端重算哈希） |
| **检测与响应** | ① 客户端完整性失败时上报埋点并降级为"受限模式"；② 对同一账号短时间内的异常权益变化做风控 |

> 本方案在客户端侧验证了「本地缓存/网络响应/UI 判定/广告分支」四处均可被运行时改写；
> 根本修复必须落在**服务端权威**与**客户端完整性自校验**两条线上。
