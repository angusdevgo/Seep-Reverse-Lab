# 部署后验证清单（五场景可观察判据）

> 适用：`deploy/Deploy-ProxyDll.ps1` 部署完成后。
> 判据来源：`out/nxmain_标定说明.md`（30 点）、`out/nxservice_标定说明.md`（18 点）、`out/nxremote_标定说明.md`（4 点）。

## 0. 部署后立即核对（3 分钟）

| # | 检查项 | 命令 / 位置 | 期望 |
|---|---|---|---|
| 0.1 | 代理日志出现且点位全部 APPLIED | `nx_main\项目B_guard_sentry.log` | **按宿主进程分别统计**：<br>`项目BNxMain.exe` → `summary: applied=30 ... total=30`<br>`项目BNxService.exe` → `summary: applied=18 ... total=18`<br>（同一日志文件累积两个进程的记录，合计 48 条 `[APPLIED ]`） |
| 0.2 | RemoteService 日志 | `nx_main\项目B_guard_version.log` | `summary: applied=4 already=0 mismatch=0 total=4`（启动云控相关组件后生成） |
| 0.2b | 四态校验（可选） | 任一 `项目B_guard_*.log` | 正常部署只应出现 `[APPLIED ]`；重复加载同一进程会出现 `[ALREADY ]`；出现 `[MISMATCH]`/`[OUTOFRANGE]` 说明版本不符（见第 6 节） |
| 0.3 | 无 MISMATCH / OUTOFRANGE | 同上两个日志 | 计数均为 0（若不为 0 说明版本不符，见第 6 节） |
| 0.4 | EXE 哈希未变 | `certutil -hashfile 项目BNxMain.exe SHA256` | `f1f507b9fa2a43f47369904a08ff65fd18b9d61282a9e1b91eed3e976464510b` |
| 0.5 | 官方签名仍有效 | `Get-AuthenticodeSignature .\项目BNxMain.exe` | `Valid` |

> 日志行示例：
> `[APPLIED ] nxmain_ad_gate_member_remove_ad_ok_bypass  rva=0x0012B9A3  6/6 bytes`

## 6. 异常处置

| 现象 | 原因 | 处置 |
|---|---|---|
| 日志出现 `[MISMATCH]` | 目标 EXE 与标定基线不符（版本升级 / 已被其它补丁污染） | **立即停止使用**，按 `基线取证.md` 重新标定；代理已自动跳过该点，不会写坏程序 |
| 日志出现 `[OUTOFRANGE]` | 代理被注入到非覆盖宿主（误加载） | 无需处理，代理已拒绝写入；确认未把代理 DLL 放到其它目录 |
| 日志完全没有生成 | 代理未被加载（DLL 未落位 / 应用目录优先级被覆盖） | 检查 `nx_main\sentry.dll` 与 `sentry_orig.dll` 是否同时存在；用 `Process Explorer` 查看已加载模块路径 |
| VIP 一闪又回退 | 只部署了 `sentry.dll`，`项目BNxService.exe` 未加载（或 Service 是常驻旧进程） | 完全退出 项目B 后重启；确认 Service 进程的 `项目B_guard_sentry.log` 有 18 点 APPLIED |
| 启动报"入口点缺失" | 代理未覆盖某导出（例如混用了旧版 `winmm.dll`/`winhttp.dll` 代理） | 用 `build.ps1` 重新生成；导出校验须 `EXPORT CHECK: PASS` |
| 想关闭某个可选点 | — | 设环境变量 `GUARD_DISABLE_OPTIONAL=1`（影响 `nxmain_ui_member_check_direct_b`、`nxremote_is_current_session_remote_session_false`） |
