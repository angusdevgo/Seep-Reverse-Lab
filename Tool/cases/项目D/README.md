> 案例类型：Windows PE · 客户端授权流审计（CWE-602）· 跨版本补丁迁移

## 案例定位

本项目完整记录了一次**因架构倒退导致的批量故障**，以及由此发展出的**跨版本 AOB 特征码迁移方法论**。

```
Gen 1  AOB 特征码搜索（12 条）              ← 本来是对的
   │
Gen 2  改为硬编码绝对偏移（18 点 / 31 字节）  ← ❌ 架构倒退
   │   隐含假设：「镜像布局固定」
   │   → 目标软件重编译后偏移全部失效
   │   → 叠加「无条件截断到 6,189,056 字节」
   ▼
   用户报障：不是有效的 Win32 应用程序
   │
Gen 4  回到 AOB，并补齐全部工程保障
   │   14 点双态特征码 · 3 版本验证 · PE 结构门禁
   │   版本感知备份 · 原子写入 + 三级回滚 · 差异字节白名单
   ▼
   61 项回归断言全绿 · 真实安装端到端验证通过
   │
Gen 4.1 11.3 官方新增「Serial 缺失 → 弹注册框」对抗
   │   静态 xref 断裂（vtable 间接调用）→ 转 Frida 抓调用栈定位
   │   新增第 15 位点（**可选位点**，b10/11.2 自动跳过）
   ▼
   版本自适应：b10/11.2 产物哈希不变 · 11.3 抑制弹窗
```

## 核心技法

| 维度 | 内容 |
|---|---|
| **授权校验链** | 15 个补丁位点：授权决策分支 / 试用期计算 / 6 个反篡改守护线程 / 2 处弹窗拦截 / 过期强退 / 联网验证标志 / 数据段常量 / **11.3 注册对话框抑制（可选位点）** |
| **跨版本定位** | 64 字节窗口**滑动汉明距离**（实测距离 1–6，随机期望 ≈62）；**候选必须经精确字节 + 反汇编双重确认** |
| **特征码生成** | **多版本共同稳定区** + **双态（原始/已补丁）唯一性校验**；五版本交集 378 B |
| **语义验证** | capstone 五版本指令序列比对；**全局地址咬合印证** |
| **防写坏** | PE 结构门禁 · 安全截断 · 校验和标准化 · 版本感知备份 · 原子写入 + 三级回滚 · 差异字节白名单 |
| **注册表侧** | 写入授权人姓名；Serial 键策略见 §关键发现 #7（**策略面不可靠，判定面才稳定**） |
| **运行时定位** | Frida 钩统一对话框入口 + **静态 VA → 运行时地址换算** + 回溯栈抓取（含 SEH handler 噪声排除） |
| **版本自适应** | `AobPoint.Optional` 可选位点机制：一套引擎适配**五个版本**，无版本分支判断 |

## 关键发现

| # | 发现 | 价值 |
|:--:|---|---|
| 1 | 小版本重编译导致 **非均匀代码位移**（−896 ~ +64） | 证明固定偏移方案不可行 |
| 2 | 单版本特征码会混入**重定位指针** | 特征码必须取多版本共同稳定区 |
| 3 | 相距 4 字节的相邻位点，特征码**互相包含** | 必须合并为单条条目 |
| 4 | **COMDAT 折叠**使两个函数序言逐字节相同 | 该位点不能靠序言锚定，需左侧扩展 |
| 5 | 流传的原版 Crack 写入的 PE 校验和是**无效值** | 官方原版与标准算法 100% 吻合，应写正确值 |
| 6 | 升级后遗留的旧版备份 → **回滚点错版** | 引入版本感知备份 + 还原守卫 |
| 7 | **注册表策略面会被官方针对性封堵** —— 工具「删除 Serial」的策略在 11.3 恰好命中新增弹框分支 | 版本演进应优先在**判定面（二进制分支）**打桩 |
| 8 | 成员函数经 **vtable 间接调用**时静态 xref 完全断裂 | 改用 Frida 动态抓调用栈，一次命中 |
| 9 | 补丁在**孤立目录**运行时弹出集成文件告警 | 必须做三组对照实验排除测试假阳性 |
| 10 | 数据段**非均匀填充漂移**使模糊匹配锁定到早 2 字节的近邻位置（汉明距离仅 2，看起来「完美」） | 模糊匹配只能产生**候选**，必须经精确字节 + 反汇编双重确认（见 §8.3） |
| 11 | 官方内置更新器**静默覆盖**已打补丁的主程序，授权态回落 Trial | 客户端特权态天然易失；必须关闭自动更新 + 引擎 fail-closed |
| 12 | 版本越多，**共同稳定区越小**（118 B → 24 B） | 结构性权衡；只要双态唯一性仍成立，短特征码在工程上安全 |

## v1.6.1 演进：build 16 代码重排 + `.text` 段 +245 KB 膨胀

> **现象**：官方静默更新到 build 16 后，已激活环境重新弹出注册对话框（资源 ID 138）。

### 第一判断：先查引擎，再查目标

用 v1.6.0 的五版本特征码表扫描 build 16.3 → **16 位点仅命中 5 个** → fail-closed 引擎**零字节写入** → 二进制保持官方原版 → 权益回落 `Trial` → 启动弹框。

> **教训**：用户看到的是「弹框」，根因却是「补丁没打上」。
> 排查顺序必须是「先看引擎命中数，再看目标行为」，反过来会误判成厂商新增了对抗。

### 结构差异量化：这是重编译级别，不是补丁级别

| 节区 | b15.3 | b16.3 | 变化 |
|---|---:|---:|---:|
| `.text` | `0x2931FC` | `0x2D05EC` | **+250,864 B（+245 KB）** |
| `.rdata` | `0xE500E` | `0xEB79A` | +26,508 B |
| `.data` | `0x136DC` | `0x1407C` | +2,464 B |
| `.rsrc` | `0x22D738` | `0x22D738` | **±0** |
| `.reloc` | — | — | +10,736 B |

**关键线索**：`.rsrc` **逐字节不变** → 对话框资源仍在原位 → 弹框来自**代码路径**，直接排除「厂商更换对话框」的假设。

历史对照：b12 → b15 仅 +1,536 B，b10 → b12 完全同尺寸。**+245 KB 是历次更新中最大的结构变化**。

### 四项关键适配

1. **十个失配位点定位**：以 b15.3 已验证偏移为锚，64 B 窗口滑动汉明 → 全部命中于 **汉明 3–10**（随机期望 ≈62），补丁字节全部一致 ⇒ 纯位移。
   **但段内位移非均匀**：`+0x1D0` ~ `+0x5E0`（跨度 3 倍）——禁止全表平移。
2. **capstone 语义验证方法修正**：线性反汇编因 capstone 遇不可解码字节提前停止而失步（39,100 条指令 / 2.9 MB ≈ 74 B/指令）。
   改用**局部定向反汇编**（多起点探测，取恰好起始于补丁地址的指令）后，15 个代码位点全部命中指令边界且助记符与 b15.3 完全一致。
3. **六版本特征码重生成**：位点 1 左侧 IAT 绝对地址常量 `0x69` → `0x6D`，左扩展自动由 2 B 收缩为 1 B（多版本稳定区机制按设计工作）。
4. **签名长度上限 48 B**：最大扩展 502 B（位点 16 达 135 B，过度脆弱）；最短充分 142 B（4–6 B 签名，误命中风险）；**选定 48 B 上限 → 366 B / 平均 22.9 B**。

### 关键决策：签名长度的两种失败模式不对等

| 失败模式 | 后果 | 严重性 |
|---|---|---|
| 签名过短 → 误命中错误位置 | **写坏二进制** | 🔴 致命 |
| 签名过长 → 新版本失配 | 干净中止，零字节写入 | 🟢 可恢复 |

⇒ 优先保证「不误命中」（下限由双态唯一性 1/1 硬门禁保证），同时用上限约束「不过度特化」。

### 验证

- **零回归**：五版本修补产物 SHA-256 与 v1.5.1 **逐字节一致**；
- **双实现交叉验证**：C# 引擎与独立 Python 参考实现产出**同一哈希** `8F77A3E8…A029B5EE`；
- **差异字节白名单**：32 字节重叠差异 + 10,608 B 签名截断，**白名单外 0**；
- **回归断言**：98 → **118 项**（新增 build 16 端到端版本块 + 六版本哈希基线锁定）；
- **真机验证**：`idmvers` = `v6.43b16 Full`，冷启动零弹窗，`IDMan.exe.BAK` 正确刷新为 b16 原版。

## v1.6.2 演进：build 18 零改动吸收（48 字节上限的回报）

> **现象**：官方静默更新到 build 18（build 17 被跳过）后，**注册对话框 + 试用倒计时弹窗**
> 同时回归，`idmvers` 回落 `v6.43b18 Trial`。
>
> **这是本项目历史上第一次以零字节签名表改动吸收的新版本。**

### 结构差分：方向翻转

| 节区 | build 16.3 | build 18.3 | 增量 |
|---|---:|---:|---:|
| `.text` RawSize | `0x2D0600` | `0x2D6600` | **+24,576** |
| `.rdata` RawSize | `0xEB800` | `0xEBE00` | +1,536 |
| `.data` / `.rsrc` | — | — | **±0** |
| `.reloc` RawSize | `0x39E00` | `0x3A000` | +512 |
| 文件体积 | 6,490,480 | 6,517,104 | +26,624 |

段内代码位移 **`−0x320` ~ `−0x9A0`（全负）** —— 与 build 16 的 `+0x1D0` ~ `+0x5E0`
**方向完全相反**；数据段则 `+0x6600`。

### 三种可能，实测排除了两种

| 假设 | 验证方式 | 结果 |
|---|---|---|
| ① 引擎失效（同 build 15/16） | 现有签名表原样扫描 | **16/16 精确命中，汉明距离 0** → 签名无需改动 |
| ② 新增反篡改 | UTF-16 资源字符串差分 | 仅 10 条新增，**无一与授权/试用/更新相关** → 无新对抗 |
| ③ 判定链语义变更 | capstone 逐位点反汇编 | 15 个代码位点助记符与 b16 完全一致，`.data` 常量块逐字节相同 → 语义未变 |

结论：**纯粹是二进制重排**。适配工作量为「更新版本声明 + 加测试基线」。

### 48 字节上限为什么扛住了 2.5 KB 位移

| 方案 | 全表体积 | 平均长度 | 风险 |
|---|---:|---:|---|
| 最小充分 | 142 B | 8.9 B | **误命中 → 写坏二进制** |
| 最大扩展 | 502 B | 31.4 B | 漂移脆弱 → 每版必重建 |
| **选定 48 B 上限** | **366 B** | **22.9 B** | 两侧风险均压低 |

build 18 的位移幅度**大于** build 16，签名表却零改动存活 —— 这是 v1.6.1
那个「显式设上限并记录理由」决策的直接兑现。

### 验证

- **精确命中**：16/16，汉明 0，重生成流水线未触发；
- **产物**：6,506,496 B · SHA256 `DED287E0…F03CE954` · csum `0x006371AE`；
- **差异审计**：33 字节（26 补丁 + 4 校验和 + 4 安全目录），**白名单外 0** + 10,608 B 签名截断；
- **回归断言**：118 → **133 项**；
- **旧版本零回归**：六个历史版本修补哈希逐字节不变；
- **真机验证**：冷启动 16 秒仅 1 个窗口（无 `(Trial)` 后缀），零弹窗，`idmvers = v6.43b18 Full`。

> **教训**：零改动 ≠ 零工作。表没改，但定位、语义、取证、回归、真机五道验证一道不能少；
> 而「签名长度上限」这类看似细节的参数决策，其回报往往在几个版本之后才显现。

## v1.6.0 演进：全栈中英双语国际化架构

> **需求**：工具面向国际开源社区发布，需为海外用户提供原生英文界面，同时不破坏现有中文体验。

### 架构设计

| 维度 | 方案 |
|---|---|
| **字典载体** | 纯代码内嵌 `Dictionary<string,string>`，**零 `.resx`、零附属程序集**，保持单源码 `csc.exe` 秒级编译 |
| **语言探测** | 首启读 `lang.cfg` → 缺失则回退 `CultureInfo.CurrentUICulture`（`zh*` → 中文，其余 → 英文） |
| **持久化** | `lang.cfg` 单行文本 `zh` / `en`，与既有 `idm_path.cfg` 风格一致，已加入 `.gitignore` |
| **热切换** | 侧边栏品牌区 `[ 🌐 EN / 简 ]` 胶囊按钮 → `I18n.SetLanguage()` → 重入 `BuildUI()` → 回填日志 → `SwitchTab(记录索引)` |
| **日志翻译** | `Log()` 前置钩子调用 `I18n.TranslateLog()`，对运行时动态拼接的日志行做 115+ 条模式替换 |

### 关键工程决策

1. **为什么不用 `.resx` 卫星程序集**：会破坏“单文件绿色免安装”卖点，且 `csc.exe` 单命令编译流程需额外资源编译步骤。
2. **热重绘而非重建窗口**：仅重入 `BuildUI()` 并 `this.Content = root`，保留窗口位置、尺寸与生命周期；`txtConsole.Text` 在重绘前备份、重绘后回填，避免日志丢失。
3. **日志必须走翻译层**：底层引擎（AOB 补丁 / ACL 冻结 / 备份归档）的日志是**运行时字符串拼接**产物，无法预先做资源化，故采用「前缀模式匹配 + 分段替换」策略，并刻意把宽泛规则（如 ` 处` → ` entries`）**放在最后**，避免污染专用规则。
4. **CLI 同步国际化**：新增 `-lang <zh|en>` 参数，`-help` 输出与系统区域联动。

### 验证

- 回归断言由 89 项扩充至 **98 项**（新增 9 项国际化单元测试：英文问候语纯净度、横幅/补丁行/授权行/冻结行翻译、双向切换幂等性）；
- 实机验证：英文模式下 Tab 1/2/3 全英文渲染，控制台日志 `[System Init] …` 纯英文输出，无乱码无错位。

## v1.5.1 演进：新增位点 16（更新定时器切断）+ 代理报错根因修复

> **现象**：用户开启「屏蔽更新」后，启动或下载偶发弹出「无法连接到代理服务器 127.0.0.1:XXXX」，必须手动关闭屏蔽更新才能正常使用。

### 根因与误区纠偏

1. **`LastCheckQU` 清理副作用**：民间激活工具盲目清理该键；实测证实为 **Last Check Quick Update** 时间戳，被删后 项目D 认为从未检查过更新，启动时即强行发起更新探测！
2. **`CheckUpdtVM = 0` 的民间传闻**：反汇编证实 `项目D.exe` **从来不会读取 `CheckUpdtVM`**，仅在超期时向其单向写入 `"10"`；该键对阻断更新毫无作用。
3. **后台更新撞死代理**：强行触发的后台更新尝试走系统代理，代理未运行/端口变动时即弹出报错窗口。

### 根治方案

- **位点 16（启动更新定时器切断）**：定位 `SetTimer(0x22, 225000ms)` 分支，将 `jne` (`75 19`) 改为 `jmp` (`EB 19`)，定时器根本不会被注册，从源头杜绝后台更新！
- **注册表规范化**：从清理列表中剔除 `LastCheckQU`，并写入合法的当前 Unix 时间戳。

## v1.5.0 演进：静默自动更新 + 五版本特征码迁移

> **现象**：用户环境「新版本出现特权状态离线验证失败」—— `idmvers` 回落 `v6.43b15 Trial`。

### 根因链

```
官方内置更新器静默下载新版
   ↓
覆盖已打补丁的主程序（签名完整 ⇒ 纯净原版）
   ↓
旧引擎特征码仅覆盖 b10/11.2/11.3 → 扫描 5/15 命中
   ↓
引擎 fail-closed 熔断（零字节写入）
   ↓
用户得到「未激活但未损坏」的二进制 —— 即「工具用不了」
```

> **反事实**：若引擎强行套用旧偏移，b15 的代码段会被写坏，
> 用户拿到的将是**彻底无法启动**的二进制。fail-closed 在此役价值尽显。

### 两项关键适配

| # | 挑战 | 处置 |
|:--:|---|---|
| 1 | **共同稳定区收窄**：b15 重编译使五版本逐字节一致区域变小 | 特征码改由**五版本交集**生成（总字节 1,050 → **378 B**）；双态唯一性仍为硬判据 |
| 2 | **数据段填充漂移**：位点 #14 前方多出 2 个零字节，模糊匹配偏早 2 字节（错误偏移 `0x379546`） | 改用**精确锚点搜索**（`AVCDownloadComponents` 字符串）定位到 **`0x379524`**，capstone 双确认 |

### 五版本结果

| 版本 | 生效位点 | 产物 SHA256 | 回归 |
|---|---|---|---|
| build 10 | 14/15 | `712BD0D9…` | **与 v1.4.0 逐字节一致** |
| build 11.2 | 14/15 | `3470B5B8…` | **与 v1.4.0 逐字节一致** |
| build 11.3 | 15/15 | `641A6D97…` | **与 v1.4.0 逐字节一致** |
| build 12.3 | 15/15 | `B9B6F951…` | 新增支持 |
| **build 15.3** | **15/15** | `5005D219…` | 新增支持 |

**真机实测**：`项目D.exe` 6,201,712 → **6,191,104 字节**；
`idmvers` `v6.43b15 Trial` → **`v6.43b15 Full`**；启动无任何弹窗。

### 客户侧加固建议

模式一已写入 `CheckUpdtVM = 0` 关闭自动更新，避免下次静默升级再次冲掉本地特权态。
这印证了 CWE-602 的核心风险：**客户端特权态天然易失且不可信**，
正确修复必须在服务端建立权威校验闭环（Server-Side Authority）。

## v1.4.0 演进：11.3 注册对话框对抗链

> **现象**：工具授权后主程序可用，但 11.3 启动即弹「注册 项目D」对话框（资源标题原文为 `Internet Download Manager Registration`）。

### 根因

11.3 **新增**了一条对抗逻辑：启动时若注册表不存在 `Serial` 值 → 直接弹注册对话框（资源 138）。

而工具早期策略是「**删除 Serial**」（依据「无 Serial + 有 FName = 终身授权」）——
该假设在 b10/11.2 成立，**恰好命中 11.3 新增的弹框分支**。

| 版本 | "Serial 缺失" 分支行为 | 打补丁后 |
|---|---|---|
| b10 | 仅清理句柄，继续 | 无弹窗 |
| b11.2 | 仅清理句柄，继续 | 无弹窗 |
| **b11.3** | **`call <弹框>`** | **弹窗** ← 缺陷 |

### 定位（静态撞墙 → 动态破局）

静态 xref 因 vtable 间接调用完全断裂，转用 Frida 钩 `CreateDialogIndirectParamA`，
抓取回溯栈一次命中触发点 `0x48E271`；再于该点读取全局指针，解出被加密的值名 = **`"Serial"`**。

### 修复

第 15 位点：`74` → `EB`（`je` → `jmp`，永远走「Serial 已存在」路径）。

因 b10/11.2 该处代码布局完全不同（特征码零命中），引擎引入 **`AobPoint.Optional`**：
必需位点全中才放行；可选位点未命中则跳过，不阻断。

### 版本自适应结果

| 版本 | 生效位点 | 差异字节 | 产物 SHA256 |
|---|---|---|---|
| b10 | 14/15（可选跳过） | 30 | `712BD0D9…` **未变** |
| b11.2 | 14/15（可选跳过） | 30 | `3470B5B8…` **未变** |
| b11.3 | **15/15** | **31** | `641A6D97…` |

> 三版本端到端验证 + 61 项回归断言全绿 + 真实安装实测无弹窗。

### 假阳性排除

补丁产物在**孤立目录**运行时曾弹出 `cannot find 21 file(s)...` 集成告警。
经三组对照实验确认：补丁让程序正确走「已注册」路径 → 继续执行集成文件自检；
**孤立目录**自然自检失败，真实安装目录（191 文件齐全）不会报。
