### 3.1 位移分布

| 对比 | 代码段位移 | 数据段位移 |
|---|---|---|
| build 10 → build 11.2 | **−384 ~ −896**（跨度 512） | **+512** |
| build 11.2 → build 11.3 | **−48 ~ −96**（跨度 48） | **0** |
| build 11.3 → build 12.3 | **0**（位点完全重合） | **0** |
| build 11.3 → build 15.3 | **+0x184 ~ +0x4F0**（全部为正） | **+0x648** |

> build 11.3 / 12.3 是同一代码布局的微修订；build 10 → 11.2 是较大重编译。
> build 15 为**又一次大幅重编译**，位点位移不再有简单规律（数据段位移远大于代码段），
> 这也再次证明**硬编码偏移方案在结构上不可行**。
> build 16 进一步验证了这一点：**段内位移跨度达 3 倍**（`+0x1D0` 到 `+0x5E0`），
> 任何「算一个偏移差再全表平移」的做法都会导致大部分位点错位。
> build 18 则把位移**方向整体翻转**（代码段 −0x320 ~ −0x9A0），
> 进一步说明「按上一版本位移趋势预测下一版本」的做法同样不可靠。

### 3.2 ⚠ 数据段「非均匀填充漂移」陷阱（build 15 实证）

位点 14 所在的数据块在 build 15 中**前方新增了 2 个零填充字节**：

```
b11.3/b12.3 : … 6E 74 73 40 40 │ 00 00 00       │ 01 00 00 00 │ 01 00 00 00 │ 1E 00 00 00 …
b15.3       : … 6E 74 73 40 40 │ 00 00 00 00 00 │ 01 00 00 00 │ 01 00 00 00 │ 1E 00 00 00 …
                                      ↑ 多出 2 字节
```

**后果**：朴素「滑动汉明距离」会把 64 字节窗口锁定到**早 2 字节的近邻位置**
（汉明距离仅 **2**，远低于「≤ 8 即命中」的判据），从而给出**错误补丁偏移 `0x379546`**。
该处字节为 `01 00 00 00 01 00 00 00`，而期望是 `01 00 00 00 1E 00 00 00`。

**修复纪律（已固化进流水线）**：

1. 模糊匹配（汉明距离）**只能用于产生候选位置**，不能作为最终结论；
2. 候选位置必须经**期望字节精确匹配**验证；
3. 字节不符时，改用**精确锚点搜索**（如 `AVCDownloadComponents` 字符串 + 常量对）重新定位；
4. 最终必须经 **capstone 反汇编语义对照**确认与基线一致。

> 本例中正确偏移为 **`0x379524`**（精确锚定 + 反汇编双确认）。

### 3.3 build 16 代码重排 + 签名长度上限决策（v1.6.1 实证）

#### （1）失配的真相：不是新反篡改，是代码重排

官方静默更新到 build 16 后，五版本特征码表仅 **5/16 命中**，引擎 fail-closed **零字节写入**，二进制保持原版 → 权益回落 Trial → 启动弹框。

**判定依据**：`.rsrc` 段 VSize 与 RawSize **逐字节不变**（`0x22D738`）。
若厂商更换了对话框，`.rsrc` 必然变化；它没变，说明弹框来自**代码路径**。

#### （2）位点 1 的左扩展收缩：IAT 绝对地址的活教材

```
b15.3 : … 04 20 6D 00 [69] 00 85 C0 …
b16.3 : … 04 20 6D 00 [6D] 00 85 C0 …
```

那 4 字节是 `FF 15 04 20 6D 00`（`call dword ptr [0x006D2004]`）的**间接调用目标地址**，
随代码重排而变。六版本交集因此只保留 `0x00` 一字节，**左扩展由 2 B 自动收缩为 1 B**。

> 这是「多版本共同稳定区」机制在按设计工作——它**不需要人工干预**就能自动剔除版本相关常量。

#### （3）签名长度上限：必须显式做出的取舍

| 策略 | 总字节 | 平均 | 位点 16 长度 | 风险 |
|---|---:|---:|---:|---|
| 最大扩展 | 502 B | 31.4 B | 135 B | 过度特化，未来版本极易失配 |
| 最短充分 | 142 B | 8.9 B | 5 B | 4–6 B 签名，**误命中风险** |
| **上限 48 B（选定）** | **366 B** | **22.9 B** | **48 B** | **平衡** |

**判据：两种失败模式的严重性不对等。**

| 失败模式 | 后果 | 严重性 |
|---|---|---|
| 签名过短 → 误命中错误位置 | **写坏二进制** | 🔴 致命 |
| 签名过长 → 新版本失配 | 干净中止，零字节写入 | 🟢 可恢复 |

因此：**优先保证「不误命中」（下限由双态唯一性硬门禁保证），同时用 48 B 上限约束「不过度特化」**。

#### （4）操作数补丁 ≠ 操作码补丁

位点 12 的上下文：

```
B8 01 00 00 00 9B E9 D5 00 00 00 B8 [01] 00 00 00 A3 …
                                      ↑ 补丁点
```

`B8 01 00 00 00` = `mov eax, 1`，补丁字节落在**立即数**上（`01` → `00`）。

> 若验证逻辑一律要求「补丁地址 == 指令起始地址」，会把此类位点**误报为未对齐**。
> 必须显式区分：
> - **操作码补丁**（`jz`→`jmp`、`push`→`ret`）：要求落在**指令边界**
> - **操作数补丁**（立即数 / 位移）：要求落在**所属指令的字节范围内**，且 opcode 不变

#### （5）线性反汇编会失步

最初对 `.text` 做线性反汇编建索引：2.9 MB 仅产出 39,100 条指令（≈74 B/指令，正常应 3–4 B/指令）——
说明 capstone 在遇到不可解码字节时**提前停止**。

**正确做法：局部定向反汇编**——从补丁地址前 `0..15` 字节的多个起点分别反汇编，取恰好起始于补丁地址的指令：

```python
for back in range(0, 16):
    va0 = va_patch - back
    for ins in md.disasm(d[fo0:fo0+64], va0):
        if ins.address == va_patch:
            return ins.mnemonic, ins.op_str, bytes(ins.bytes)
        if ins.address > va_patch:
            break
```

## 4. 核心机制

### 4.1 授权分支（决策入口）

```asm
call dword ptr [0x694004]        ; 授权状态查询
85 C0        test eax, eax       ; ← 补丁 85 → 33 (xor eax,eax)
0F 85 1B010000  jne 0x2E180      ; 补丁后 eax=0 且 ZF=1 → 永不跳转
C6 85 4FF5FFFF 01  mov byte ptr [ebp-0xAB1], 1   ; 恒置「已授权」标志
```

补丁 `test eax,eax` → `xor eax,eax` 后 `eax=0`、`ZF=1`，`jne` **永不跳转**，`[ebp-0xAB1]` 恒被置 1。

### 4.2 试用期计算

```asm
A1 DC9C7700      mov eax, dword ptr [0x779CDC]   ; 读「试用状态标志」
F7D8            neg eax
1BC0            sbb eax, eax                     ; 0 → 0x00000000 ; 非0 → 0xFFFFFFFF
83 E0 0F        and eax, 0xF                     ; ← 补丁点
83 C0 0F        add eax, 0xF                     ; ← 补丁点
A3 E09C7700      mov dword ptr [0x779CE0], eax   ; 写「试用天数常量」
```

| 分支 | 原逻辑 | 结果 |
|---|---|---|
| 标志 = 0 | `0 & 0xF + 0xF` | **15 天** |
| 标志 ≠ 0 | `0xFFFFFFFF & 0xF + 0xF` | **30 天** |

**补丁**：`83 E0 0F 83 C0 0F` → `B8 FF FF FF 7F 90`
= `mov eax, 0x7FFFFFFF` + `nop` → 试用天数恒为 **0x7FFFFFFF（永久）**

> **地址换算印证**：`[0x779CDC]` → RVA `0x379CDC` → 文件偏移 **`0x378CDC`**；
> `[0x779CE0]` → RVA `0x379CE0` → 文件偏移 **`0x378CE0`**。
> 与数据段补丁点**完全咬合**。
> 换算公式：`文件偏移 = 节区 RawPtr + (VA − ImageBase − 节区 VA)`

### 4.3 守护线程 / 看门狗（6 个）

均为标准 MSVC SEH 函数序言：

```asm

68 <SEH 作用域表>   push <scope table>
64 A1 00000000     mov eax, fs:[0]
50                 push eax
81 EC 64010000     sub esp, 0x164
```

| 名称 | build 10 偏移 | 函数体提示 |
|---|---|---|
| 守护线程 A | `0x74920` | `sub esp, 0x164` |
| 守护线程 B | `0x753C0` | `sub esp, 0x64` |
| 守护线程 C | `0x7BC00` | `sub esp, 0x164` |
| 守护线程 D | `0x7CA50` | `sub esp, 0x1C4` |
| 看门狗关联函数 | `0x834E0` | `sub esp, 0x1C4` |
| 守护线程 F | `0x131C60` | — |
| 守护线程 E | `0x842E0` | `push ebp / mov ebp,esp / and esp,-8`（非 SEH 型） |

补丁 `6A` / `55` → `C3` 使函数**入口即返回**，线程启动后立即终止。

> ⚠️ **COMDAT 折叠**：「守护线程 D」与「看门狗关联函数」前 24 字节**逐字节相同**且共享同一 SEH 作用域表。两点特征码无法依赖函数序言，只能靠左侧前一个函数的尾部锚定。

### 4.4 试用状态标志 + 天数限制常量（数据段）

```
原值: 01 00 00 00 | 1E 00 00 00     (标志 = 1, 天数 = 30)
补丁: 00 00 00 00 | FF FF FF 7F     (标志 = 0, 天数 = 0x7FFFFFFF)
```

> 两点相距仅 **4 字节**，必须合并为单条 8 字节条目，否则 AOB 特征码互相包含无法唯一定位。

**build 15 填充漂移**：该常量块前方多出 2 个零填充字节（详见 §3.2），位点从 `0x378EDC` 移至 **`0x379524`**。
该位点是本次跨版本迁移中**唯一一个模糊匹配给出错误结果的位点**，已改用精确锚点定位。

### 4.7 注册对话框对抗链（build 11.3 新增 · 第 15 位点）

> **这是 11.3 相对 11.2 唯一新增的对抗逻辑**，也是「已激活却弹注册框」缺陷的根因。

#### 4.7.1 触发链

```
RegOpenKeyExA(HKCU, "SOFTWARE\Internet Download Manager")   ← 该键通常不存在
  └─ 失败 → 回退到全局句柄 HKCU\Software\DownloadManager
       ├─ RegQueryValueExA(hKey, "Serial")   ─ 成功 → 跳过（已注册路径）
       └─ RegQueryValueExA(全局键, "Serial") ─ 成功 → 跳过（已注册路径）
                 └─ 两次都失败 → call <注册对话框宿主函数>
                        └─ 弹出对话框资源 138
                             "Internet Download Manager Registration"
```

#### 4.7.2 反汇编（三版本对照）

| 版本 | 第二次读取后的分支 | 语义 |
|---|---|---|
| b10 | `jne <清理路径>` → 关句柄后**继续** | 无弹窗逻辑 |
| b11.2 | `jne <清理路径>` → 关句柄后**继续** | 无弹窗逻辑 |
| **b11.3** | `je <继续>` 否则 `call <弹框>` | **新增弹窗** |

b11.3 原始指令：

```asm
0048E265  FF1504406900    call RegQueryValueExA
0048E26B  85C0            test eax, eax
0048E26D  740C            je   0x48e27b        ← 补丁点：74 → EB
0048E26F  8BCB            mov  ecx, ebx
0048E271  E8AAB3FFFF      call 0x489620       ← 弹注册对话框
0048E276  E9BD000000      jmp  0x48e338
0048E27B  897DDC          mov  [ebp-0x24], edi   ← 已注册路径，继续
```

#### 4.7.3 补丁语义

`74` → `EB`（`je` → `jmp`）：**永远走「Serial 已存在」路径**，跳过弹框且不改变后续逻辑。

#### 4.7.4 为什么必须做成「可选位点」

b10 / 11.2 的同一位置是**句柄清理路径**（`test esi,esi / cmp / RegCloseKey`），
代码布局与 11.3 完全不同，特征码在那两个版本上**零命中**。

若强行要求命中，会让引擎在 b10 / 11.2 上拒绝打补丁。
因此引擎引入 `AobPoint.Optional`：

```
必需位点全部命中 → 放行写入
可选位点未命中   → 打印「跳过可选位点（本版本无此逻辑）」，不阻断
```

#### 4.7.5 特征码

| 项 | 值 |
|---|---|
| 原始态 | `8B0DE86C780051FF150440690085C0740C` |
| 补丁态 | `8B0DE86C780051FF150440690085C0EB0C` |
| 补丁偏移 | 15 |
| 期望 → 补丁 | `74` → `EB` |
| 命中范围 | 仅 11.3（b10/11.2 为 0） |

#### 4.7.6 关键教训：注册表策略不能替代二进制补丁

早期版本工具的策略是「**删除 Serial 值**」，依据是「无 Serial + 有 FName = 终身授权」。
该假设在 b10 / 11.2 成立，**但 11.3 已被官方针对性封堵**——删除 Serial 恰好命中了新增的弹框分支。

> **结论**：注册表状态是**服务端可变更的策略面**，二进制分支才是**稳定的判定面**。
> 版本演进时应优先在判定面打桩，注册表只做辅助。

## 5. 注册表侧

### 5.1 关键反直觉发现

目标程序对 `Serial` 键执行**非对称公钥校验** —— 写入任何伪造序列号都会触发「使用假冒序列号注册」弹窗。

### 5.2 正确解法

```
1. 删除 Serial 键
2. 清理遥测/黑名单键：
   scansk, tvfrdt, radxcnt, ptrk_scdt, LastCheckQU,
   scTime, NextCheck, BList, md5pks, itb_r, ncl_r
3. 仅写入 FName / LName / Email
4. 设置 CheckUpdtVM = 0, LstCheck = "0"
```

**键路径**：`HKCU\Software\DownloadManager`

### 5.3 版本感知备份

`项目D.exe.BAK` 必须与当前安装版本一致，否则回滚点与「一键还原」均指向错误版本 —— 详见 `reverse-engineering.md` §6.4。

## 6. PE 结构侧

### 6.1 签名剥离

- 清除 `IMAGE_DIRECTORY_ENTRY_SECURITY`（数据目录索引 4）的 `VirtualAddress` 与 `Size`
- 移除物理追加在文件尾部的 **10,608 字节** Authenticode 证书块
- 文件由 `6,199,664` 截断为 `6,189,056`（build 11 为 `6,189,568`）

### 6.2 PE 校验和

**必须**在「全部补丁 + 截断」之后用标准算法重算。

| 文件 | 存储校验和 | 标准算法计算 | 结论 |
|---|---|---|---|
| 官方 build 10 原版 | `0x005ECD00` | `0x005ECD00` | ✅ 吻合 |
| 官方 build 11.2 原版 | `0x005EF1D7` | `0x005EF1D7` | ✅ 吻合 |
| 官方 build 11.3 原版 | `0x005E9C44` | `0x005E9C44` | ✅ 吻合 |
| **原版 Crack v20.7 产物** | `0x005F0BEA` | `0x005EBDA3` | ❌ **无效值** |

> 穷举 4 种输入状态 × 16 种算法变体，**均无法复现 `0x005F0BEA`** ⇒ 原版 Crack 写入的是无效校验和。
> 而它能工作 ⇒ 目标程序与 Windows **均不校验该字段**。

## 7. 补丁集演进（Gen 2 → Gen 4）

| 项 | Gen 2（旧） | Gen 4（新） |
|---|---|---|
| 定位方式 | **硬编码绝对偏移** | **AOB 双态特征码** |
| 条目数 | 18 点 | **14 点** |
| 代码/数据点 | 15 点 / 24 字节 | **14 点 / 24 字节**（合并数据段） |
| PE 头点 | 3 点 / 7 字节（硬编码偏移与值） | **0 点**（动态求解） |
| 支持版本 | 仅 build 10 | **build 10 / 11.2 / 11.3** |
| 产物差异字节 | 31（build 10） | **30 / 30 / 31** |

```
Gen2 旧补丁集（18 点 / 31 字节）
├─ [硬编码] 0x150   PE Checksum 校正    ← 值写死为 EA 0B 5F（无效校验和）
├─ [硬编码] 0x191   Security 目录 RVA
├─ [硬编码] 0x194   Security 目录 Size
├─ 代码段 13 点 / 19 字节
└─ 数据段 2 点（拆分）0x378CDC + 0x378CE0

                    ↓ 重构

Gen4 新补丁集（14 点 / 24 字节）
├─ [动态] CheckSum 偏移 = OptionalHeader + 0x40
├─ [动态] Security 目录 = DataDirectory[4]
├─ [动态] 校验和值 = 微软标准算法重算
├─ 代码段 13 点 / 19 字节
└─ 数据段 1 点（合并）0x378CDC..0x378CE3 (8 字节)
```
