## 一、鉴权协议结构（实测抓包）

### 1.1 传输层

```
TCP  <AUTH-SRV>:4001        ← 明文，无 TLS，无握手
```

### 1.2 请求（客户端 → 服务端）

| 偏移 | 长度 | 值（示例） | 语义 |
| :--- | :--- | :--- | :--- |
| `+0x00` | 4 | `E8 03 00 00` | **命令号** = 1000（登录 / 卡密校验） |
| `+0x04` | 4 | `CB 02 00 00` | **载荷长度** = 715 |
| `+0x08` | 715 | 高熵密文 | 卡密 + 机器码 + 版本号 + 摘要 |

### 1.3 响应（服务端 → 客户端）

| 偏移 | 长度 | 值（示例） | 语义 |
| :--- | :--- | :--- | :--- |
| `+0x00` | 6 | `01 02 04 02 05 04` | **固定魔数**（协议指纹） |
| `+0x06` | 4 | `1C 00 00 00` | **总长** = 28 |
| `+0x0A` | 18 | 高熵密文 | 状态码 + 服务端下发文案 |

> **注意**：错误提示「卡号不存在」在本地镜像中**检索不到**（GBK / UTF-16LE 双检索为空），
> 说明该文案由服务端响应解密后直接渲染 → 客户端完全信任服务端文本。

### 1.4 协议指纹速查

| 指纹 | 用途 |
| :--- | :--- |
| 端口 `4001` + 命令号 `1000` | 该类在线卡密验证系统的常见特征 |
| 响应魔数 `01 02 04 02 05 04` | 可用于同族软件快速识别 |
| 本地无验签表（无 AES S-box / 无 RSA blob） | 判定"服务端响应未被密码学签名" → 伪造服务端理论可行 |

## 二、补丁点全表

### 2.1 最终补丁集（3 处 / 22 字节）

| # | 虚拟地址 | 原始字节 (Hex) | 补丁字节 (Hex) | 语义 |
| :--- | :--- | :--- | :--- | :--- |
| **P1** | `0x00401290` | `83 7D FC 00 0F 84 4D 02 00 00` | `C7 45 FC 01 00 00 00 90 90 90` | `cmp [ebp-4],0` + `je 0x4014E7` → `mov dword [ebp-4],1` + `nop×3` |
| **P2** | `0x0041AC81` | `0F 8D 34 01 00 00` | `E9 35 01 00 00 90` | `jge 0x0041ADBB` → `jmp 0x0041ADBB` |
| **P3** | `0x0041AE05` | `0F 8D 34 01 00 00` | `E9 35 01 00 00 90` | `jge 0x0041AF3F` → `jmp 0x0041AF3F` |

### 2.2 逐处上下文

**P1 —— 登录卡密裁决点**

```asm
0x00401272  call 0x401549                  ; 联网校验卡密，返回 0/1
0x0040128A  mov  eax, dword ptr [ebp-0x10]
0x0040128D  mov  dword ptr [ebp-4], eax    ; ← 服务器裁决结果落栈
0x00401290  cmp  dword ptr [ebp-4], 0      ; ★ 本地裁决
0x00401294  je   0x004014E7                ; ==0 → 「卡号不存在」
0x0040129A  ...                            ; !=0 → 成功分支
```

补丁后：
```asm
0x00401290  mov  dword ptr [ebp-4], 1      ; 强制置"通过"
0x00401297  nop / nop / nop
0x0040129A  ...                            ; 恒走成功分支
```

**P2 / P3 —— 授权心跳复检裁决点（函数 `0x0041AB86` 内）**

```asm
0x0041AC3C  push 1 ; call 0x41AFA6         ; 复检请求 #1
0x0041AC7D  cmp  dword ptr [ebp-0xC], 1
0x0041AC81  jge  0x0041ADBB                ; ★ P2
0x0041ADC0  push 3 ; call 0x41AFA6         ; 复检请求 #2
0x0041AE01  cmp  dword ptr [ebp-0xC], 1
0x0041AE05  jge  0x0041AF3F                ; ★ P3
```

## 三、AOB 特征码（版本漂移时重新定位）

> 地址 = 命中地址；该 PE 无重定位，段内偏移固定。

| 补丁 | 特征码 (AOB) | 定位说明 |
| :--- | :--- | :--- |
| **P1** | `83 7D FC 00 0F 84 4D 02 00 00` | 全匹配，唯一 |
| **P2** | `89 65 F8 68 00 00 00 00 68 FF FF FF FF B8 02 00 00 00` → 其前 `0F 8D 34 01 00 00` | 用前置锚点定位 |
| **P3** | `83 C4 04 83 7D F4 01 0F 8D 34 01 00 00` | 含前置 `add esp,4` + `cmp`，唯一 |

> ⚠️ P2/P3 的裸特征码 `83 7D F4 01 0F 8D 34 01 00 00` 相同，**必须靠前置锚点区分**。

## 四、落点时机与外部进程修补骨架

### 4.1 时序判据

```
启动进程 → 每 20 ms 轮询 ReadProcessMemory(0x0041AB86, 3)
        → 命中 55 8B EC（函数序言 push ebp; mov ebp,esp）
        → 立即写入 P1 / P2 / P3 → 回读校验
```

> 未解密时该处是随机密文；**用字节判据同步比 `sleep` 稳**。

### 4.2 关键 API 序列（Python ctypes）

```python
# 1) 启动（必须脱离调用方控制台，否则批处理退出时会连带杀掉目标）
k32.CreateProcessW(target, None, None, None, False,
                   CREATE_DETACHED_PROCESS,  # 0x00000008
                   None, workdir, byref(si), byref(pi))

# 2) 打开
h = k32.OpenProcess(PROCESS_ALL_ACCESS, False, pi.dwProcessId)

# 3) 等待解密完成
while rpm(h, 0x0041AB86, 3) != b'\x55\x8B\xEC': time.sleep(0.02)

# 4) 写入（段已是 RWX，仍建议先 VirtualProtectEx 兜底）
wpm(h, 0x00401290, bytes.fromhex('C745FC01000000909090'))
wpm(h, 0x0041AC81, bytes.fromhex('E93501000090'))
wpm(h, 0x0041AE05, bytes.fromhex('E93501000090'))

# 5) 回读校验
assert rpm(h, 0x00401290, 10) == bytes.fromhex('C745FC01000000909090')
```

### 4.3 回读校验期望值

| 地址 | 回读应为 |
| :--- | :--- |
| `0x00401290` | `C7 45 FC 01 00 00 00 90 90 90` |
| `0x0041AC81` | `E9 35 01 00 00 90` |
| `0x0041AE05` | `E9 35 01 00 00 90` |
