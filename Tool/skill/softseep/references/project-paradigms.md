# 项目实例经验库（九类架构脱敏复盘）

> 来源：softseep 主控 §六 | 加载时机：判型后需要对照范式 / 复现路径 / 报告模板时


> **脱敏说明**：以下 A/B/C/D 四型均来自个人实战经验沉淀，已**去除产品名、公司名、可反查哈希**，仅保留 RVA / 字节序列 / 检测方法 / 统计 / 复现步骤。以「项目 A~D」代称，当作个人经验分享，防止误传与误用。所有偏移为教学范例，**实际复现以现场实测哈希为准**。

### 项目 A 型 —— 经典单进程纯离线客户端（Monolithic Offline）
* **架构特征**：
  * 单一可执行文件（PE32/PE64），无后台服务守护，完全支持单机断网离线运行；
  * 核心功能代码 100% 完整打包于本地二进制中，门禁判定与业务逻辑物理同处一室。
* **脆弱性成因 (CWE-602)**：
  * 注册算法与校验私钥/盐值直接硬编码在二进制内部；
  * 核心门禁依赖单个标量函数返回值（`isValidLicense() -> BOOL`）或全局状态标志位。
* **实战复盘与穿透要点**：
  1. **算法逆向还原**：通过 IDA 反编译提取校验算法逻辑，可无损推导离线激活算法；
  2. **指令级单点修补**：定位 `isValidLicense` 核心判定跳转指令（如 `TEST EAX, EAX` + `JZ/JNZ`），通过代理 DLL 将其篡改为强制直通跳转或无破坏返回值覆写（`b0 01 c3`）；
  3. **时间戳常数锁定**：针对试用期检测机制，将有效截止时间直接打桩为极值常数（`b8 7f e6 85 f4`，返回 2099 年时间戳）。

### 项目 B 型 —— 现代多进程混合客户端（Hybrid Multi-Process）
* **架构特征**：
  * 复杂的“前台 UI (Qt/CEF) + 核心代理服务 + 后台虚拟化 Daemon (Service/Driver)”多进程拓扑结构；
  * 兼具“云端账号同步”与“离线降级可用”双轨设计，组件间通过 IPC（命名管道、本地 RPC）通信。
* **脆弱性成因 (CWE-602 + BFLA)**：
  * **本地状态盲信**：UI 进程为了弱网可用，将特权状态缓存于本地文件或内存单例中，缺乏强数字签名保护；
  * **跨进程边界单向信任 (BFLA)**：后台虚拟机特权服务盲目信任来自前端 UI 的 RPC 指令，未在服务进程内独立进行服务端凭证验签。
* **实战复盘与穿透要点**：
  1. **代理 DLL 进程分流过滤**：
     * 由于 `version.dll` 会被所有子进程（UI 进程、后台服务进程）同时隐式加载，**必须在 `DllMain` 工作线程中调用 `GetModuleFileNameW` 严格判定进程名**；
     * 针对主 UI 进程与后台 Service 进程分别施加定制化的打桩逻辑，严禁跨进程无差别打桩；
  2. **三层协同打桩（UI + 反序列化 + 本地缓存）**：
     * **Layer 1**：在 UI 虚函数处挂钩，点亮特权视觉与解锁按钮（`mov al, 1; ret`）；
     * **Layer 2**：在网络响应反序列化解析点打桩，截获云端返回的 Profile 并强制覆写为有效等级，防止云端轮询将状态冲刷掉；
     * **Layer 3**：修正本地读取缓存的逻辑，确保护航离线断网不降级；
  3. **C++ ABI 防崩红线**：
     * 现代 C++ 广泛使用 STL 容器与智能指针，严禁对非标量函数（如涉及 `std::string` 或容器赋值的函数）直接覆写 `ret`，必须精准定位纯标量返回函数，杜绝 `0xC0000005` 崩溃。

### 项目 C 型 —— 资源模板本地化 + 显示层伪造（Resource-Template Suite）

* **架构特征**：
  * 单进程大型 C++ GUI（自研 UI 类 + 自带皮肤引擎），伴多组件协同（独立授权库 `.dll`、修复库、Shell 扩展、SFX 模块）；
  * 界面文案不硬编码，走多语言资源文件 + `TEXT_*` 占位符模板引擎；
  * 版本/特权状态以**单一全局状态对象的数值字段**落地（本次为 `state+0x120`），UI 视觉与广告抑制均直接读该值。
* **脆弱性成因 (CWE-602)**：
  * **版本状态单点落地**：虽然对版本号做了双射位重排掩码混淆（`0x98`→`100`、`0x1B20`→`10000`），但决策仍完全依赖客户端内存中的单一数值；
  * **授权库仅依赖本地对称加密 + 硬件指纹**（Blowfish 密钥混入磁盘序列号），算法原语与解密流程完全内嵌客户端；
  * **模块加载路径不收敛**：对 `version.dll` 等基础系统库采用宽松查找，未声明 `LOAD_LIBRARY_SEARCH_SYSTEM32`。
* **实战复盘与穿透要点**：
  1. **版本落地三岔口枚举**：同一个 `mov dword ptr [rsi+120h], imm32` 模板会在三处出现（PRO / ENT / STD 兜底），必须**全量枚举再选最稳的一处打**，而不是只改分支跳转。
  2. **显示层需求下沉到输出 API**：当需求是“关于对话框展示指定授权信息”时，**不要去改语言模板，也不要去 Hook STL 模板替换函数**，直接在 `SetDlgItemTextW(hDlg, 0x527, ...)` 这一最终落笔点做 IAT Hook——此处是纯宽字符串，零 ABI 风险（详见 Step 6）。
  3. **控件类名必须运行时实测**：ID 名含 `STATIC` 的控件实测为 `Edit`，静态假设必翻车（见第五章 陷阱 3）。
  4. **换行必须走 CRLF + 运行时兜底**：`zig-clang` 会吞掉 `\r` / `\x000D`，而 Win32 `Edit` 又不认纯 LF，必须 `\u000D\u000A` 字面量 + `NormalizeCrlf()` 双保险（见第五章 陷阱 1）。
  5. **文案外部可配**：把最终文案抽到与代理 DLL 同级的 `version_patch.ini`，支持 `\n` 转义与 UTF-8，交付后用户可零重编译微调排版。

### 项目 D 型 —— 壳保护 + 多策略激活套件（Packed & Multi-Strategy Activator）

* **架构特征**：
  * 目标为单进程原生客户端，但发布物带 **MPRESS 壳**（`.MPRESS1` 主压缩节 + `.MPRESS2` 解压辅助节），字符串被压缩不可静态提取，入口点代码经混淆；
  * 目标本体的授权逻辑与外部套件均独立成两个项目：**主体客户端** + **激活套件**；
  * 套件本身也带壳，作为加载器/启动器存在，动态解析 API、可能移除目标数字签名。
* **脆弱性成因 (CWE-602 + 壳可脱 + 守护可断）**：
  * **壳保护可脱**：MPRESS 为商业压缩壳，非 VM 化虚拟化，脱壳后代码可读；
  * **单点授权分支**：授权校验函数返回值单字节决定通过（`test eax,eax` 比较点）；
  * **试用期常量可改写**：剩余天数/状态标志为本地常量，可就地最大化；
  * **守护线程可阻断**：看门狗/守护线程入口为单字节指令起始（`6A`=`push`），改为 `C3`=`ret` 即静默阻断；
  * **联网验证为本地标志位**：联网校验结果存于本地标志（01=需校验 → 00=跳过），非服务端权威。
* **实战复盘与穿透要点**（三策略合一）：
  1. **策略一·二进制指令修补**：18 个补丁点 / 共 31 字节，分四类作用：
     * **签名剥离**：证书目录 RVA/Size 清零 + 尾部截断 10,608 字节 + PE 校验和重算；
     * **授权分支强制通过**：单字节 `85`→`33`（`test eax,eax` → `xor eax,eax`，恒真）；
     * **试用期常量最大化**：`mov eax,0x7FFFFFFF; nop`（天数变天文数字）；状态标志 `01`→`00`、天数 `1E`→`FFFFFF7F`；
     * **守护/看门狗阻断**：7 处入口 `6A`→`C3`、`55`→`C3`（`push`/`mov ebp,esp` → `ret`，静默返回，**不 freeze 进程**）；
     * **弹窗/强退绕过**：条件跳转 `74`→`EB`（`je`→`jmp`）、`0F85`→`90E9`（`jne`→`nop;jmp`）；
     * **联网验证标志置零**：`01`→`00`。
  2. **策略二·注册表授权登记**：写入授权人姓名到注册表，**必须同时删除 Serial 键**（残留会触发假冒序列号弹窗）；
  3. **策略三·ACL 冻结试用期**（零二进制改动，保哈希）：精确锁定注册表 CLSID 键与时间戳，固定 30 天试用状态，支持官方在线升级；
  4. **安全机制**：打补丁前严格比对 `Expected` 原始字节，不符自动中断回滚；首次修补自动建 `*.BAK` 原始母版备份。

### 项目 E 型 —— VM 保护 + 在线核验 → patch 路线（EXECryptor Hybrid）

* **架构特征**：
  * 主程序（x64 原生 C++）+ 独立授权运行时 Helper（共享内存 IPC 服务）；
  * **EXECryptor 混合授权**：序列号绑定机器码（RSD），验签私钥在厂商侧，验签逻辑被 **VM 虚拟化**（VM stub 静态不可还原）；
  * 激活时 Helper 向厂商 `verify.php` 在线核验，返回 JSON `{result:0|2|3, LicType, ExpiryMonth/Year}`。
* **脆弱性成因 (CWE-602)**：
  * **判定集中**：`IsRegistered` 函数是**唯一**注册状态判定源，被 CheckRegistration（2 处）与 Activate（2 处）**四处复用**，函数尾 `mov eax, edi` 返回 `json["result"]`；
  * **LicType 失败自动归一**：局部变量先 `memset(0,0x16)` 清零，验证“失败”时 LicType=0 → 自动归一为 1（单机授权），patch 后无需额外修补；
  * **IPC 无认证**：共享内存明文 XML 请求（方法名/字段名直裸），但 Helper 验签被 VM 保护，伪造请求**无助**生成有效序列号。
* **交付策略**：**patch 版激活工具**（非算号器）—— VM 验签私钥不可得，不存在纯算号路径；patch 判定点后任意注册名/码均被识别为已注册。
* **实战复盘与穿透要点**：
  1. **单点 call 重定向**（2 处补丁，最小侵入）：
     * `0x140009E0F` `call 0x1402DE8C8`（atoi） → `call 0x140001622`（重定向到 stub）；
     * `0x140001622` 注入 stub：`B8 03 00 00 00 C3`（`mov eax,3; ret`）⇒ result 恒 3；
  2. **副作用全覆盖**：Activate（恒成功，写 RN/RC + LicType=1）+ CheckRegistration（恒已注册）—— **一处补丁覆盖四条调用路径**；
  3. **限制**：仅安装版（LicType→1）；便携版需独立 license.dat + LicType 998/999 通道，本补丁不适用。

### 项目 F 型 —— .NET 混淆 + 可逆算法 → Keygen 路线（Managed Reversible）

* **架构特征**：
  * `.NET Framework` 托管程序集（32 位），Inno Setup 安装；
  * **自家定制混淆器**（非 ConfuserEx/Reactor）：① 方法体 IL 从元数据剥离存入资源加密流，运行时 `DynamicMethod` 注入 ② 字符串 token 索引 + XOR 链解密 ③ 控制流状态机混淆；
  * v7 加密面大幅缩小（全程序集仅 5 个方法被 token 化加密），但算法**逐字节未改**。
* **脆弱性成因 (CWE-602)**：
  * **校验信息仅 95 bit 且无 RSA 签名**：19×5 bit 校验串由 email 哈希推导，无公钥签名，可离线构造；
  * **173/192 字符不校验**：头部 160 + 尾部 13 字符任意，仅 `[160:179]` 19 字符被校验；
  * **黑名单极小**：仅 6 个 MD5(email+SALT) 硬编码哈希，任意自有邮箱即规避；
  * **离线激活路径**：选项页本地 `CheckLicense` 通过即写设置 + 置 `IsPro=true`，**全程无网络**。
* **交付策略**：**纯算号器 Keygen**（因无签名，可离线构造合法密钥）。
* **实战复盘与穿透要点**：
  1. **动态解壳三步**（静态反编译只有 stub，必须跑起来）：
     * 定位方法体解密执行器（混淆类中的单例字段特征）；
     * Hook `DynamicILInfo.GetTokenFor` 记录“动态 token → 成员引用”映射——不打此补丁，解密 IL 里全是数字 token 无法对照；
     * Dump 解密后 `DynamicMethod` 的 IL 字节 + 批量还原字符串 token；
  2. **算法还原**（从 226 字节 IL）：
     * 常量：`CHARSET="23456789ABCDEFGHJKLMNPQRSTUVWXYZ"` / `SALT` / `LICENSE_LEN=192` / `CHECK_POS=160` / `CHECK_LEN=19`；
     * 三哈希：H1（多项式 x43 滚动）/ H2（ELF 风格）/ H3（4 轮移位异或）→ 拼 96 位 → 19×5bit → CHARSET 映射；
     * + MD5(email+SALT) 黑名单；
  3. **Keygen 构造**：`license = 随机160字符 + 校验串19字符 + 随机13字符`；
  4. **移植陷阱**：96 位值无法放入 `ulong`（移位量按 mod 64 处理，`<<64`==`<<0`），必须用 `BigInteger` 拼接；自洽测试（同源 Generate/Verify 互验）会掩盖移植错误，**必须用独立实现逐字符交叉验证**；
  5. **激活写入**：`%APPDATA%\...\Preferences.json` 的 `ProLicense.{Name,Email,Key}` 键——**写入前必须退出目标程序**，否则退出时会用内存设置覆盖配置文件导致回滚。

### 项目 G 型 —— 自引用校验 → 补判定点（Self-Referential Verify）

* **架构特征**：
  * 单进程 Qt 原生二进制（无壳无签名），NSIS 安装包内层 7z；
  * AppLicenser V1/V2 双层 + grace token（AES-CBC）+ **服务器签发**。
* **脆弱性成因 (CWE-602)**：
  * **自引用校验无解**：V2 本地复验 `hex(sha384(payload))==payload["key_hash"]`——校验值在载荷自身内部，离线无法构造；
  * **服务器签发不可复现**：V1 网络激活由服务器签发；
  * **本地判定点单一且无自校验**：`isLicensed` 函数入口可单点覆写。
* **交付策略**：**补丁路线**（keygen 不可行因自引用+服务器签发；补判定点即可）。与 E 型同为 patch，但**判据不同**：E 因 VM 不可逆，G 因自引用不可逆。
* **实战复盘与穿透要点**：
  1. **单点 5 字节补丁**（最小侵入）：
     * `0x140b83910`（文件偏移 0xB82D10）原始 `48 89 4c 24 08`（`mov [rsp+8],rcx`）→ 补丁 `b0 01 c3 90 90`（`mov al,1; ret; nop; nop`）；
     * 函数帧未分配即返回，无栈平衡问题；调用方统一收到"已授权"；
  2. **防回退守卫**：`--guard` 注册登录项 `HKCU\...\Run\...Guard` → 启动静默 `--silent --fix` 幂等修复；`--revert` 由 `.bak` 还原；
  3. **静态方法降级**：Ghidra 全量分析在 27MB Qt 上耗时过长 → 改用 **Python 确定性扫描**：PE 节表→`.rdata` 定位字符串 VA→扫 `.text` 所有 `LEA r64,[rip+disp32]`→rizin `pd` 局部反汇编，**零分析器依赖秒级完成**。

### 项目 H 型 —— 公钥替换 Keygen（Embedded-Pubkey Replacement）

* **架构特征**：
  * x64 Qt 原生二进制（无壳无签名），内置 `LicensingClient`（CryptoPP Ed25519）；
  * **公钥不以明文存储**，以 58 字节密文内嵌（15 个立即数 mov），运行时代码解密还原。
* **脆弱性成因 (CWE-602)**：
  * **公钥保护可逆**：`cipher = pub XOR keystream`，keystream 由密文+明文直接推导，**无密钥材料** → 任意新公钥都能加密回写；
  * **验签消息=明文 JSON**：postProcess 的 A/C 两次 XOR 与验签前一次 XOR 完全抵消，消息就是签名时的 JSON 字节，无摘要/格式加固；
  * **设备绑定弱**：machineid 仅由 MachineGuid 可预测哈希派生；
  * **反调试 XOR 路径确定**：无调试器时 XOR 路径确定，可精确复现。
* **交付策略**：**公钥替换 Keygen**（与 F 型算法可逆 Keygen 不同——这里走的是**密码学公钥替换**，本质是"换锁配钥匙"）。
* **实战复盘与穿透要点**：
  1. **9 处文件偏移写回新公钥密文**（0x2493C8..0x249400，前 8 dword + 第 9 dword 首字节）：33 字节 = 新公钥 32B + NUL，用推导出的 keystream 加密回写；
  2. **设备码构造**：`blake2s("...","1",MachineGuid)[-6:].hex()` → `XXXX-XXXXXXXXX` 格式（15 字符，自洽：`(len-dash-2)/2=6` 恒成立）；
  3. **激活码构造**：`code = '0' + check_char + '-' + base64(sig(64) ‖ gzip(JSON) XOR sig)`；
  4. **可选持久化**：4 个失败出口（RVA 0x245a14/ada/b12/b22）`C7 07 imm32`→`0x00000000`，使状态检查总返回成功；
  5. **移植陷阱**：离线激活**不落盘**（仅在内存，重启回免费版），需 `--persist` 配套；
  6. **动态验证要点**：frida 读 Qt 容器务必先确认 `+8` 是 data 指针（非 `+16`）；反调试分支会改变 XOR 路径，**务必无调试器复现**。

### 项目 I 型 —— RSA 弱模 + 验签入口补丁（Weak-Modulus RSA）

* **架构特征**：
  * X64/ARM64 DLL（Explorer 加载），7-Zip SFX 安装，授权逻辑全在组件 DLL；
  * RSA 签名验签（CNG `RSAPUBLICBLOB`）+ CONST 异或混淆 + MAGIC + 机器绑定。
* **脆弱性成因 (CWE-602)**：
  * **RSA 模数弱但不致命**：n=1016bit（pollard rho 命中 2663），但 q1(1005bit) 未分解 → 现实中不可伪造签名；
  * **key 无自洽校验段**（对比 F 型 19 字符校验串）→ **算号器路线不成立**；
  * **验签入口可补**：`Ordinal_102` 验签函数可注入激活态。
* **交付策略**：**验签入口补丁**（算号不可行；走补丁注入激活态）。
* **实战复盘与穿透要点**：
  1. **本地要素复现**：`LicenseHash=md5hex(key)` · A=磁盘序列号(word-swap) · B=SMBIOS UUID → 请求串 R=LicenseHash+md5hex(A)+md5hex(B)（96 hex）；
  2. **验签滑窗理解**：本地验证 0x1b 滑窗步长 1，匹配 `LicenseHash + CONST/机器要素 + MAGIC`；
  3. **Ghidra 切分陷阱**：栈变量 `local_b8/local_98/local_78/iStack_58/asStack_54` 实为**同一 128B 输出 P'**，勿当独立变量；
  4. **CNG blob 布局**：`RSA1‖BitLength‖cbPublicExp=3‖cbModulus=128‖cbPrime1=0‖cbPrime2=0`（非 CryptoAPI RSA1）；
  5. **试用判定**：首装时间戳=注册表键最后写入时间（CPU 拓扑派生 PINGROUP）；试用 100 天；系统时间早于键时间戳或年≥2028 跳过过期判定（容忍时钟回拨）；
  6. **动态验证**：`ctypes GetProcAddress(dll,ordinal 102)` 直接调 patched DLL（ret=1, out[0]='1'）；explorer 重启×2 状态保持。

### 范式库补充 A —— 漏洞检测通用流程（四步法）

> 上述 A/B/C/D/E/F/G/H/I 九型回答“**怎么破**”，本节回答“**怎么找、找到几个、怎么复现**”——
> 三者合起来才构成一份可交付的 CWE-602 走查。

| 步 | 动作 | 判据 / 产物 |
| :--- | :--- | :--- |
| **D1 资产指纹基线** | 记录 MD5/SHA256 · ImageBase · 映像大小 · 签名状态 · 版本号 | 无此基线，后续所有偏移**不可复算**；换版本的产物不可比较 |
| **D2 攻击面枚举（八面）** | 沿 8 个面逐面扫：① 加载期（DLL 搜索顺序 / KnownDlls）② 内存期（可写可执行页 / 缓解策略）③ 调用期（函数入口完整性 / CFG）④ 存储期（注册表 / 配置 / 许可文件）⑤ 网络期（端点 / 心跳 / 黑名单）⑥ 壳期（熵剖面 + 指纹）⑦ VM期（VM stub 识别）⑧ .NET期（IL 加密 / 运行时注入） | 产出**脆弱面清单**（每面至少一条判据） |
| **D2.5 关键判据三问（决定 keygen vs patch）** | 在 D2 与 D3 之间必答：<br>**① 自引用校验？** 校验值是否在载荷自身内部（如 `sha384(p)==p["key_hash"]`）→ 命中则 keygen 死路<br>**② 公钥存储形式？** 明文 / 密文 / **可逆密文**（keystream 可推导）→ 可逆则可走公钥替换 Keygen<br>**③ RSA 模数可分解？** n<1024 弱但未必可分解（pollard rho/sympy factorint）→ 可分解才走算号 | 产出 **四分决策**：补丁 / 算号 / 公钥替换 / 不可行 |
| **D3 决策点收敛** | 从脆弱面下钻到具体 **RVA / 函数 / 字节序列**：<br>· 全局对象地图（状态对象 + 偏移）<br>· 鉴权链路 ASCII 流（输入 → 解密 → 校验 → 落地）<br>· 批量模板扫描（如同一 `mov dword ptr [rsi+120h], imm32` 会在多处出现） | 产出**补丁点候选表**（附原始字节） |
| **D4 可利用性判定（四分决策）** | 由 D2.5 三问导出：</br>· **patch 路线**——单点/多点补丁（VM不可逆/自引用/RSA不可分解）<br>· **算号路线**——可逆算法或可分解弱模<br>· **公钥替换 Keygen**——公钥可逆密文内嵌<br>· **不可行**——服务端权威+无本地判定点，明说 | 产出**路线决策** + 残差风险 |

**五面扫描的对应工具**：

| 面 | 工具 / 手段 | 典型发现 |
| :--- | :--- | :--- |
| 加载期 | 导入表 + 搜索顺序分析 | `version.dll` / `sentry.dll` 可劫持 |
| 内存期 | `Get-Process`/节区属性 + 缓解策略查询 | 未开 `ProcessDynamicCodePolicy` |
| 调用期 | IDA 反编译 + Inline Hook 探测 | 函数头无完整性校验 / 无 CFG |
| 存储期 | 注册表监控 / 配置文件对比 | 特权状态落地字段 |
| 网络期 | 字符串扫端点 + 抓包 | 心跳 / 黑名单 / 下发通道 |
| **壳期** | 节表熵剖面 + 壳指纹表 | MPRESS/UPX/Themida 等可脱/不可逆判定 |
| **VM期** | Ghidra headless + VM stub 识别（反编译为不可执行伪码） | EXECryptor/Themida VM 静态不可逆，需旁路 |
| **.NET期** | ilspycmd + Harmony `GetTokenFor` Hook + dnlib ildump | 方法体 IL 加密 / 运行时注入，需动态解壳 |
| **密码学期** | 字符串扫 `RSA1`/Ed25519 公钥 blob + 模数位宽检测 | 公钥明文/密文内嵌；n<1024 弱模待分解 |

### 范式库补充 C —— 复现路径归档（九型）

#### C-9 · 项目 I 型复现（RSA 弱模 + 验签入口补丁）

```
【基线】7z 解 SFX（归档偏移 0x14000）；记录 DLL 指纹；备份

        n bit_length=1016；pollard rho 命中 2663；
        sympy factorint q1(1005bit) 无 <1e6 因子 → 不可分解 → 算号不可行
【本地要素复现】
        LicenseHash = md5hex(key)（默认值 >0x1e 才迁移）
```
