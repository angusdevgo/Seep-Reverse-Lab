# UPDATE Skill — 智能经验总结、自主演进判型与全自动同步规范

> 本 Skill 是 Seep Reverse Lab 独有的自动化运维与发布中枢。
> **核心使命**：用户不需要关心技术细节分类，只需下达自然语言指令：
> *“使用 update skill，总结本次逆向授权分析经验，同步到工作台”*
> Skill 依据当前逆向会话/工作目录下的成果特征，**自主判断是合并演进还是新建案例**，并全自动完成脱敏、文档维护、自检与推送。

---

## 一、 核心铁律与前置安全门禁

### 1. 任务语境驱动原则（Task-Context Driven）
- 依据**当前逆向任务的上下文**（分析目录、调用栈、已生成的 PoC、生成的报告、修改的代码）自主提炼经验；
- **严禁全盘盲目扫描**系统私有目录；仅处理当前逆向任务产生的成果资产。

### 2. 个人私有技能与凭据强隔离黑名单（Strict Blacklist）
以下个人专属/私密资产**严禁以任何理由同步或推送到 Seep 工作台和 GitHub**：
- 🚫 **个人专属 Skill**：`github`、`green`、`tg-reader`、`muse`、`ui` 等；
- 🚫 **个人凭据与认证**：`models.json`、`auth.json`、各类 API Key、Token、私有 SSH 密钥；
- 🚫 **未脱敏的目标文件**：任何带有真实公司名称、个人商业客户软件名或未脱敏文件绝对路径的工程。

### 3. 大文件与构建垃圾门禁（Volume & Artifact Gate）
- **单文件体积限制**：严禁提交单个文件大于 50MB 的未压缩二进制；单个文件大于 100MB 触发硬性熔断；
- **构建垃圾自动清理**：提交前自动剔除或跳过 `__pycache__`、`*.pyc`、`.venv/`、`node_modules/`（除已归档的 zip 外）、`.vs/`、`bin/Debug/` 等临时编译产物。

## 二、 自主判型算法：【合并演进】 vs 【新建独立案例】

当用户说“总结本次逆向授权分析经验，同步到工作台”时，**由 Skill 自发分析并做出以下决策**，无需用户干预：

```
                    提取本次逆向成果与技术特征
                                │
                                ▼
         ┌──────────────────────────────────────────────┐
         │ 1. 软件标识与既有项目比对                     │
         │    是否属于已有项目 (项目A ~ 项目I) 的同源软件? │
         └──────────────────────┬───────────────────────┘
                                │
               ┌────────────────┴────────────────┐
               │ 是                              │ 否
               ▼                                 ▼
┌──────────────────────────────┐    ┌──────────────────────────────┐
│ 2. 架构与对抗深度比对        │    │ 【决策 B: 新建独立案例】     │
│  - 底层语言是否改变?         │    │  · 归档为 Tool/cases/项目X/  │
│    (如 C++ 重构成 Flutter)   │    │  · 案例计数: N -> N+1        │
│  - 授权模型是否推翻?         │    │  · 双语 README 追加新案例行   │
│    (如 单机离线 变成 强云端) │    └──────────────────────────────┘
└──────────────┬───────────────┘
               │
      ┌────────┴────────┐
      │ 核心架构未变    │ 彻底推翻重构
      ▼                 ▼
┌──────────────────────────────┐
│ 【决策 A: 原地版本演进合并】 │
│  · 归档在既有项目目录        │
│    (如 项目D/v2/ 或 docs/)   │
│  · 案例总数保持不变 (N)      │
│  · 突出“攻防拉锯/差分升级”   │
│  · 更新 README 说明与演进注记│
└──────────────────────────────┘
```

### 判型细节规则表：

| 命中特征 | 自主决策 | 归档位置 | 计数器规则 | 文档表达 |
|---|---|---|---|---|
| 与已有案例同源，仅是厂商升级版本、修补偏移、增加检测点 | **决策 A：合并演进** | `Tool/cases/项目X/`（增补 `v2/` 目录或差分文档） | 案例总数 $N$ 保持不变 | 在中英 README 中将该项目描述更新为 `(v1.0 → v2.0 攻防演进)` |
| 全新独立软件，或同名软件但底层架构完全推翻（如 Win32 $\rightarrow$ Flutter） | **决策 B：新建独立案例** | `Tool/cases/项目(N+1)/` | 案例总数 $N \rightarrow N+1$ | 在中英 README 案例表格与目录树中追加全新一行 |
| 提炼出的成果属于高复用逆向方法论或自动化脚本 | **决策 C：沉淀到工具层** | `Tool/skill/` 或 `Tool/mcp/` 或 `Tool/scripts/` | 对应组件计数更新 | 更新对应的 Tool/Skill/KB 矩阵与 Badge |

## 三、 自动化执行流水线（SOP）

整个执行过程无需用户敲击命令，Skill 自发驱动以下 5 步：

### Step 1：经验提炼与合规审查
1. **自动提取**当前分析任务的核心要素：
   - 漏洞与脆弱性原理（CWE-602 决策位点、RVA 偏移、函数符号）；
   - 复现代码（Frida 探针、内存补丁 Hex、代理 DLL 工程）；
   - 防护与对抗特征（壳类型、反调试绕过）；
2. **强制脱敏扫描**：
   - 自动将私人用户名 `C:\Users\Angus` 替换为通用便携路径；
   - 抹除真实公司名称与商业软件原名，转译为代号（如 `项目X`）；
   - 扫描并剔除所有实网 Token、密钥或凭据。

### Step 2：按决策自发落地归档
- 若为 **决策 A（合并演进）**：在目标既有案例目录下归档新版本 PoC 与 Diff 报告；
- 若为 **决策 B（新建独立案例）**：创建 `Tool/cases/项目[Next]/` 并生成规范化结构；
- 若目标已在 `Seep/` 工作区内部：**自动感知幂等性，跳过重复复制**。

### Step 3：单一真值源 (SSOT) 统计与文档维护
以**物理磁盘与真实代码**作为单一真值源，禁止凭记忆猜数字：
- 统计 `Tool/cases` 目录数、`Tool/skill` 技能数、`seep_mcp_server.py` 工具注解数；
- 自动更新 `README.md` 与 `README.zh.md` 中的 Badge 徽标与矩阵表格；
- 联动在 `references/project-paradigms.md` 中补充技术卡片。

### Step 4：全量健康自检门禁（check.ps1）
在推送前，后台自动运行：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\check.ps1
```
- 确认全部 37+ 项检查均为绿色 `[√ PASS]`，且输出 `[READY / 完备就绪]`；
- 若有任何一项失败，立即阻断，绝不带病推送到 GitHub。

### Step 5：动态代理探测、变基与推送上云
自动调用 `setup/sync-hub.ps1`：
- 动态探测本地 10808/7897/7890 代理端口；
- 本地提交变更 $\rightarrow$ 执行 `git pull --rebase origin main` 保证线性历史；
- 安全推送到 GitHub 远程仓库！
